# Судалгааны тайлан: WCAG 2.2-д нийцсэн универсал хүртээмжийн plugin

*Огноо: 2026-11-04. Энэ тайлан нь Хүртээмж (hurteemj) plugin-ийн архитектурын шийдвэр бүрийн үндэслэлийг тайлбарлана.*

---

## 1. Стандартын одоогийн байдал

| Стандарт | Төлөв (2026-11) | Plugin-д хамаарах байдал |
|---|---|---|
| **WCAG 2.2** | W3C Recommendation (2023-10-05, 2024-12-12-нд шинэчилсэн) | **Үндсэн зорилт.** Бүх 86 шалгуурыг каталогт оруулсан |
| **ISO/IEC 40500:2025** | WCAG 2.2-ыг ISO стандарт болгон баталсан (W3C 2025-10-21-нд зарласан). 2023 оны 10-р сарын хувилбартай ижил | WCAG 2.2-тай ижил агуулга тул тусад нь ажиллах шаардлагагүй |
| **ISO/IEC 40500:2026** | 2024-12-ын WCAG 2.2 хувилбарыг 2026 оны сүүлээр ISO болгохоор хүлээгдэж байна (баталгаажаагүй) | Агуулгын өөрчлөлтгүй, засварын шинж чанартай |
| **WCAG 3.0** | Working Draft (2026-03-03). W3C-ийн хэлснээр бүрэн стандарт болоход хэдэн жил шаардлагатай. WCAG 2-ыг хүчингүй болгохгүй | Одоо хэрэгжүүлэхгүй; архитектур нь дүрмийг модуль байдлаар нэмэх боломжтой |
| **EN 301 549** (ЕХ) | Одоогоор WCAG 2.1-ийг иш татдаг. Дараагийн хувилбар WCAG 2.2-ыг ашиглахаар хүлээгдэж байна | WCAG 2.2 AA нь 2.1 AA-г бүрэн агуулдаг (4.1.1-ээс бусад) тул давхар хангана |
| **European Accessibility Act** | 2025-06-28-наас хэрэгжиж эхэлсэн | ЕХ-д үйлчилгээ үзүүлдэг монгол байгууллагад хамаарна |
| **НҮБ-ын CRPD** | Монгол Улс 2009 онд нэгдэн орсон | 9-р зүйл: мэдээлэл, харилцаа холбооны хүртээмж |
| **Хөгжлийн бэрхшээлтэй хүний эрхийн тухай хууль** (2016) | Хүчин төгөлдөр | Мэдээллийн хүртээмжийн ерөнхий үүрэг. Техникийн стандартын хувьд WCAG 2.2 AA-г зорилт болгохыг зөвлөнө (хуулийн тодорхой шаардлагыг хуульчаар баталгаажуулна уу) |

### WCAG 2.2-ын гол өөрчлөлтүүд (2.1-тэй харьцуулахад)

- **9 шинэ шалгуур:** 2.4.11 Focus Not Obscured (Minimum, AA), 2.4.12 Focus Not Obscured (Enhanced, AAA), 2.4.13 Focus Appearance (AAA), 2.5.7 Dragging Movements (AA), 2.5.8 Target Size (Minimum, AA), 3.2.6 Consistent Help (A), 3.3.7 Redundant Entry (A), 3.3.8 Accessible Authentication (Minimum, AA), 3.3.9 Accessible Authentication (Enhanced, AAA).
- **4.1.1 Parsing хасагдсан** — орчин үеийн браузер ба туслах технологи HTML-ийн алдааг өөрсдөө засдаг болсон. Иймээс давхардсан ID-г зөвхөн ARIA/label-д ашиглагдсан үед (4.1.2, 1.3.1) зөрчил гэж үзнэ.
- **Тоо:** A = 31, AA = 24, AAA = 31; нийт 86. AA түвшинд нийт 55 шалгуур.

**Plugin дахь хэрэгжилт:** 9 шинэ шалгуурын 7-д нь автомат/хэсэгчилсэн дүрэм бий:

| SC | Хэрхэн шалгадаг | Засвар |
|---|---|---|
| 2.4.11 / 2.4.12 | sticky/fixed header-footer-ийн өндрийг `scroll-padding`-тэй харьцуулна | `scroll-padding` тохируулж, `focusin` үед далдлагдсан эсэхийг `elementFromPoint`-оор шалгаж гүйлгэнэ |
| 2.4.13 | CSSOM-оос `:focus { outline: none }` дүрмийг хайна | ≥2px, хоёр өнгийн (бараан+цагаан) тойм — ямар ч дэвсгэр дээр 3:1+ |
| 2.5.7 | `draggable`, sortable сангуудын тэмдэглэгээ | Хянах (review) — хувилбар товч байгаа эсэх |
| 2.5.8 | Товшилтын талбай <24px бол 24px диаметртэй тойргийн **spacing exception**-ийг стандартын томьёогоор тооцно; өгүүлбэр доторх холбоос, UA checkbox+label-ийг үл хамааруулна | heuristic: `min-width/min-height: 24px` |
| 3.2.6 | Тусламжийн холбоосын дарааллыг `sessionStorage`-д хадгалж хуудас хооронд харьцуулна | — |
| 3.3.8 / 3.3.9 | Нэвтрэх талбар руу **бодит цуцлах боломжтой paste эвент** илгээж `defaultPrevented` эсэхийг шалгана; `autocomplete="off"`; зурган CAPTCHA | paste хоригийг цуцлах, `autocomplete="current-password"` |
| 3.3.7 | Автоматаар шалгах боломжгүй (олон алхамт процесс) | Тайланд "гараар" гэж тэмдэглэнэ |

## 2. Зах зээлийн сургамж: "overlay" хэрэгслүүдийн асуудал

Ганц мөр JavaScript-ээр "сайтыг 100% хүртээмжтэй болгоно" гэж зарладаг overlay хэрэгслүүдийн туршлагаас дараах дүгнэлт гарсан:

1. **Хууль эрх зүйн эрсдэл.** АНУ-ын Холбооны Худалдааны Комисс (FTC) 2025 оны 1-р сарын 3-нд accessiBe компанитай $1,000,000-ын шийдвэрийг зарласан. Гол шалтгаан нь бүтээгдэхүүн нь сайтыг WCAG-д нийцүүлнэ гэсэн **төөрөгдүүлсэн мэдэгдэл** байсан.
2. **Мэргэжлийн хамт олны эсэргүүцэл.** Overlay Fact Sheet-д 700–1000+ хүртээмжийн мэргэжилтэн гарын үсэг зурсан (тоо эх сурвалжаас хамаарч ялгаатай). Гол шүүмж: overlay нь дэлгэц уншигч хэрэглэгчийн өөрийн тохиргоотой зөрчилддөг, бодит эх кодын алдааг засдаггүй.
3. **Шүүхийн практик.** Overlay суулгасан сайтууд АНУ-д хүртээмжийн нэхэмжлэлээс хамгаалагдаагүй гэж олон эх сурвалж мэдээлдэг.
4. **Автомат шалгалтын хязгаар.** Ямар ч автомат хэрэгсэл (axe-core, Lighthouse, WAVE гэх мэт) WCAG-ийн асуудлын зөвхөн нэг хэсгийг илрүүлдэг. 86 шалгуурын олонх нь (жишээ нь 1.3.2 утга бүхий дараалал, 3.3.3 алдааны зөвлөмж, 2.4.6 гарчиг тайлбарлах чадвар) хүний дүгнэлт шаарддаг.

### Эдгээрээс гарсан дизайны зарчмууд

| # | Зарчим | Хэрэгжилт |
|---|---|---|
| 1 | **Үнэнч тайлан.** "100% нийцтэй" гэж хэзээ ч мэдэгдэхгүй | Тайлан бүрд `disclaimer`, SC бүрийн `status`: `fail` / `review` / `manual` / `no-issues-detected` (энэ нь "pass" биш) |
| 2 | **Зөрчил ба хянах зүйлийг ялгах** | `outcome: 'fail'` (тодорхой зөрчил) ба `'review'` (хүн шалгах). Цэвэр хуудсан дээр худал эерэг 0 байхыг тестээр баталгаажуулсан |
| 3 | **Засварын эрсдэлийн түвшин** | `safe` — утга агуулгыг таахгүй (lang, viewport, skip link, focus ring, `role=status` г.м.); `heuristic` — таамаглал (icon-оос нэр таах, өнгө өөрчлөх г.м.), сайтын эзэн хянаж асаана |
| 4 | **Ил тод, буцаах боломжтой засвар** | `ChangeLog` бүх өөрчлөлтийг бүртгэнэ; `revert()` DOM-ыг анхны байдалд оруулна (тестээр баталгаажсан); засагдсан элемент `data-hj-fixed="rule-id"` атрибуттай |
| 5 | **Эх кодыг засах нь эцсийн зорилго** | CLI ба `reportEndpoint` нь хөгжүүлэгчид selector, HTML, WCAG SC-тэй тайлан өгнө — засварыг эх кодонд шилжүүлэх |
| 6 | **Туслах технологид саад болохгүй** | Дэлгэц уншигчийг "илрүүлэх", ARIA-г бөөнөөр нэмэх зэрэг үйлдэл хийхгүй. Самбар нь Shadow DOM-д тусгаарлагдсан, `aria-modal="false"` |
| 7 | **Хэрэглэгчийн тохиргоо нь нэмэлт, орлуулагч биш** | Самбар нь хэрэглэгчид сонголт өгнө (1.4.12 текстийн зай, тодрол, хөдөлгөөн зогсоох г.м.), гэхдээ сайтын үндсэн хүртээмжийн оронд тооцогдохгүй |
| 8 | **Самбар өөрөө жишиг байх** | WCAG 2.2 AA: 44px товч, гарын бүрэн удирдлага, Esc, фокус буцаах, 320px reflow, `forced-colors`, `prefers-reduced-motion`. axe-core-оор монгол, англи хэл дээр тест хийдэг |

## 3. Техникийн шийдвэрүүд

### 3.1 Аудитын хөдөлгүүр
- **Хамааралгүй (zero-dependency).** axe-core (~550KB) оруулахгүйгээр өөрийн 65 дүрэмтэй хөдөлгүүр. Тестэд axe-core-оор хөндлөн шалгадаг.
- **Тодрол (1.4.3/1.4.6/1.4.11):** WCAG 2.x relative luminance томьёо. Арын өнгийг зөвхөн эцэг элементээр биш `document.elementsFromPoint`-ийн давхаргын стекээр тооцож, хагас тунгалаг давхаргуудыг alpha-blend хийнэ. Gradient-ийн хамгийн муу цэгийг авна. Зураг дээрх текстийг "review" гэнэ.
- **Өнгө засах (heuristic):** OKLab орон зайд зөвхөн гэрэлтэлтийг (L) хоёртын хайлтаар өөрчилж, брэндийн өнгөний аясыг хадгална.
- **Accessible name:** W3C AccName 1.2-ын хялбаршуулсан хувилбар (aria-labelledby, aria-label, label, alt, title, caption, legend, агуулга, CSS `::before/::after`).
- **1.4.12 Text Spacing:** Бодит туршилт — стандартын утгыг түр хэрэглэж, `overflow: hidden` элементийн агуулга тасарч байгааг хэмжинэ (`deep` горим).
- **2.1.1 Keyboard:** `onclick` атрибут, `cursor: pointer`, мөн сонголтоор `addEventListener` ажиглалт (CLI-д автоматаар идэвхтэй).
- **SPA:** `MutationObserver` шинэ DOM-ыг хэсэгчлэн шалгана; `history.pushState` ажиглаж бүтэн аудит хийнэ.

### 3.2 Интеграц ("ямар ч системтэй")
Ганц JavaScript файл бөгөөд ямар ч серверийн технологиос үл хамаарна:
- `<script data-*>` (статик сайт, PHP, Laravel, Django, Rails, ASP.NET, Java, Go…)
- npm/ESM (`init()`), React/Next.js, Vue/Nuxt, Web Component, WordPress plugin
- Google Tag Manager, Shopify, Drupal, Joomla — загварт нэг мөр
- CLI (`hurteemj-audit`) — GitHub Actions, GitLab CI, Jenkins-д exit code-оор
- `reportEndpoint` / `onReport` — өөрийн BI, log, Jira руу
- `altTextProvider` — өөрийн AI/caption API-тай холбох hook
- CSP `nonce` дэмжлэг — хатуу Content-Security-Policy-тэй төрийн сайтуудад

### 3.3 Монгол хэлний онцлог
- **Хэл таних:** Кирилл бичгийг монгол (ө, ү үсэг) ба орос хэлээс ялгаж `lang="mn"` санал болгоно. `mn-Mong` (монгол бичиг) BCP 47 кодыг дэмжинэ.
- **Утгагүй alt/холбоос текст:** "зураг", "энд дарна уу", "дэлгэрэнгүй" зэрэг монгол хэллэгийг таньдаг.
- **Icon толь:** `fa-search` → "Хайх", `menu` → "Цэс" г.м.
- **TTS:** Ихэнх төхөөрөмжид монгол дуу хоолой (speechSynthesis voice) байдаггүй тул хэрэглэгчид мэдэгдэнэ.
- **UI:** Монгол хэлний урт үгс 320px дэлгэцэнд таслагдахгүй байхаар (`overflow-wrap`) зохион байгуулсан.

## 4. Хязгаарлалт (үнэнээр)

- Plugin нь **WCAG-д нийцсэн гэдгийг баталгаажуулахгүй**. AA түвшний 55 шалгуурын ~17 нь зөвхөн гараар шалгагдана.
- Cross-origin iframe, хаалттай (closed) Shadow DOM, canvas доторх контентыг шалгахгүй.
- CORS-оор хамгаалагдсан гадны stylesheet-ийг (CDN) CSSOM-оор уншиж чадахгүй тул 2.4.7-ийн CSS шинжилгээ бүрэн биш.
- Heuristic засвар буруу таамаглал хийж болно (жишээ нь icon-ийн утга). Тиймээс анхдагч нь `safe`.
- Видеоны хадмал, аудио тайлбар, дохионы хэл үүсгэхгүй.

## 5. Цаашдын ажил
1. W3C ACT Rules-тэй дүрэм бүрийг уялдуулах, EARL форматын гаралт.
2. WCAG 3.0 стандарт болох үед "outcome"-д суурилсан дүрмийн модуль.
3. APCA (сонголттой, зөвлөмжийн түвшинд) тодролын шалгалт.
4. Браузерын extension (Chrome/Firefox) — ижил хөдөлгүүрээр.
5. Казах, орос, англи хэлний бүрэн орчуулга; монгол бичгийн (босоо) контентын тусгай шалгалт.
